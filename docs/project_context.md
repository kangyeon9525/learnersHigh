## 1. 프로젝트 배경 / 문제 / 목표

### 1.1 배경

러너스하이(Learners High)는 학생의 **자기주도학습 역량 향상**을 목표로, 학습의 전 과정(계획 → 입실 → 학습 → 평가 → 회고)을 하나의 태블릿 앱에서 통합 관리하는 **학습 매니지먼트 플랫폼**이다. 본 프로젝트는 상용 운영이 아닌 **시연용 프로토타입**으로, 핵심 사용자 경험과 데이터 흐름 검증에 초점을 둔다. 단, 데이터 영속화는 실제 MongoDB를 사용한다.

### 1.2 문제 정의 (Pain Points)

- 기존 학습 코칭은 **1:1 휴먼 코칭 의존**으로 비용이 높고 확장성이 낮다.
- 학생의 집중/이탈 상태를 실시간 파악·피드백할 수단이 부족하다.
- 학습 동기를 지속시킬 장치(성취·목표·성장 시각화)가 분산되어 습관 형성으로 이어지지 않는다.
- 학습 중 잦은 보상 알림이 오히려 **몰입을 방해**할 수 있다.

### 1.3 목표 (Goals)

1. AI 기반 학습 상태 감지(프로토타입에서는 시딩 데이터 재생)와 자동 리포트로 **고비용 휴먼 코칭을 대체**한다.
2. 성취·학습 목표·성장 시각화로 **지속 가능한 자기주도학습 습관**을 유도하되, **학습 중 몰입을 보호**하기 위해 보상은 **학습 종료 후 일괄 정산(정산 모달)** 한다.
3. 누적 성장 나무와 월간 성장 화분을 **하나의 통합 대시보드(전체 그림)** 로 시각화하고, 마이페이지 보관함에서 성취·성장을 회고할 수 있게 한다.
4. 프론트/백/공통 타입을 분리하고 실제 MongoDB로 영속화하여 **상용 전환 가능한 기반**을 만든다.

### 1.4 비목표 (Non-Goals)

- 실제 웹캠 영상 분석 모델 개발 (시딩 시나리오 데이터 재생으로 대체)
- 실사용자 인증 서버·결제·정산·다지점 운영 관리자 기능
- 외부 알림 채널 실연동 (대표 시나리오 목 데이터 + 실제 DB 응답으로 모의)
- 학습 진행 중 실시간 성취·목표 달성 알림 (집중 보호를 위해 종료 후 정산으로 대체)

### 1.5 성공 지표 (시연 기준)

- 핵심 플로우(입실 → 학습 → **종료 후 정산 모달** → 성장 반영 → 리포트 확인)가 끊김 없이 동작한다.
- 학습 진행 중에는 동기 부여 알림이 노출되지 않고, **학습 종료 시 정산 모달**로 신규 성취·완료 퀘스트·획득 점수·성장 단계 상승이 일괄 안내된다.
- 성장 통합 대시보드에서 **중심 누적 나무 + 주변 월간 화분**이 한 화면에 표현되고, 거기서 누적/월간 캘린더 뷰로 드릴다운할 수 있다.
- 마이페이지 보관함에서 획득 성취·완료 퀘스트·성장 변화를 회고할 수 있다.
- 학습 종료 시 백엔드 판정 결과가 **MongoDB에 영속 저장**되고 재기동 후에도 유지된다.
- API가 **실제 DB 상태에 근거한** 응답을 반환하고, 성취/목표/성장 UI가 일관되게 동기화된다.
- 시딩 데이터 기반 핵심 시나리오가 **Playwright E2E로 검증**된다.

## 2. 범위 정의

### 2.1 사용자

| 구분 | 설명 | 본 프로젝트 시점 |
| --- | --- | --- |
| **학생(주 사용자)** | 태블릿 앱으로 계획·타이머·리포트·성장 확인 | **구현 대상 (1차)** |
| 지점 관리자 | 학생 상태 알림 수신, 코칭 운영 | 알림은 목 데이터 + 실제 DB 응답으로만 모의 |
| 코치 | 코칭 클래스 운영 | 가상 예약/QR 링크 수준으로만 모의 |

> 실사용자 데이터를 수집할 수 없으므로 사용자(`users`)는 대표 시나리오로 **사전 시딩**한다.
> 

### 2.2 기능 범위 (In-Scope)

**기존 학습 관리**

- 입퇴실 및 계획 관리: 입실 후 타이머 가동, 퇴실 목적 필수 선택, 귀가 시 리포트 발송, 캘린더 계획 CRUD + 드래그앤드롭
- 학습 진행 및 상태 감지: 스톱워치/타이머, 시딩된 AI 감지 데이터 연동, 비정상 상태 **인라인 경고**(비차단·집중 시간 미적립, 타이머는 계속) — 학습 중에는 집중/이탈 경고 외 동기 부여 알림 미노출
- 학습 종료 및 이력 조회: 진척도·만족도 5점 척도, **종료 정산 모달**, 일간/월간 리포트(순공 캘린더, 효율 차트), 지점 내 가상 순위
- 라이브러리/코칭: 학습/수업/생활 카테고리 필터, 코칭 클래스 가상 예약 및 다이렉트 접속(QR/Link)

**신규 동기 부여 기능**

- 학습 성취(Milestone): 연속 N시간 등 조건 달성 시 성취 인증 + 점수. **학습 중 알림 없이 학습 종료 시 백엔드 판정**, 정산 모달로 안내
- 학습 목표(Goal): 일/주/월 자동 배정. **학습 종료/주기 종료 시 백엔드 달성 판정 + 차등 점수**, 정산 모달로 안내
- 학습 종료 정산 모달(Session Result): 학습 종료 후 이번 세션의 신규 성취·완료 퀘스트·획득 점수·성장 단계 상승을 **하나의 모달로 일괄 노출**. 모달에서 성장 대시보드/마이페이지로 이동 가능
- 누적 성장 나무(Lifetime): 점수 영구 누적 단계 성장(씨앗→새싹→묘목→성목). 성장 통합 대시보드의 **중심 오브젝트**, 누적 캘린더 뷰
- 월간 성장 화분(Monthly): 매월 초기화, 당월 점수만 반영, 월말 고정(개화) + 아카이브 뷰. 통합 대시보드에서 **중심 나무 주변 위성 오브젝트**로 배치
- 성장 통합 대시보드(Growth Garden): 캘린더 단독이 아닌 **한 화면 전체 그림(정원/풍경)** — 중심 누적 나무 + 주변 월간 화분. 누적/월간 캘린더로 드릴다운
- 마이페이지 성취·성장 보관함(Collection): 획득 성취 그리드(달성/미달성), 완료 퀘스트 이력, 성장 단계 변화/캘린더를 모아 확인하는 허브

### 2.3 범위 외 (Out-of-Scope)

- 실시간 영상 분석, 실사용자 인증/회원가입, 결제, 외부 알림 실연동, 멀티 디바이스 동기화.
- 학습 진행 중 실시간 성취/목표 달성 알림(학습 종료 정산으로 대체).
- 위 항목은 시딩 데이터/모의 응답으로 대체하되, **상용 전환 가능성을 막지 않는 인터페이스**로 추상화한다.

### 2.4 기술 스택 (요약)

- **아키텍처:** Monorepo (`frontend`, `backend`, `shared`, 루트 `e2e`)
- **언어:** TypeScript (프론트/백 전 영역)
- **프론트엔드:** React, Vue (앱/모듈 단위 공존), 상태관리 Zustand(React)/Pinia(Vue)
- **백엔드:** Node.js + Express/Fastify
- **DB:** **MongoDB + Mongoose ODM** (로컬/Docker/Atlas), 컬렉션 `users`·`studySessions`·`milestones`·`goals`·`growthStates`
- **공통 타입:** `shared/types`에 `StudySession`·`Milestone`·`Goal`·`GrowthState`와 정산 응답 DTO `StudySessionResult` 정의(`StudySessionResult`는 저장 컬렉션이 아닌 종료 응답용)
- **테스트:** Playwright(E2E), Storybook(공용 컴포넌트)
- **워크플로우:** Figma 디자인 기준 소스 + Figma MCP + Cursor 바이브코딩
- **대상:** 태블릿 가로 모드 최적화

> 상세 규칙은 `architecture.md` 참조.
> 

### 2.5 제약 조건 (데이터 시딩 전략)

| 구분 | 실제 운영 | 본 프로젝트 구현 |
| --- | --- | --- |
| AI 감지 | 웹캠 실시간 집중/이탈 감지 | **시딩 데이터 재생:** 사전 정의 시나리오 목 데이터를 DB에 시딩, 시뮬레이터가 일정 주기(예 30초)로 재생·주입 |
| 데이터 영속화 | 운영 RDBMS | **실 MongoDB:** Mongoose로 컬렉션 실제 CRUD |
| 외부 연동·데이터 수집 | 관리자 실시간 알림 / 실사용자 데이터 | **목 데이터 사전 적재 + 실제 응답:** 시딩된 DB 상태 기반 실제 API 응답, Playwright로 흐름 검증 |

**고정 제약**

- 비즈니스 로직(점수 계산, 성취/목표 판정, 성장 단계 산정, **종료 정산 집계**)은 **반드시 백엔드**에서 수행. 프론트는 렌더링 담당.
- **집중 보호:** 학습 진행 중에는 성취/목표 달성 알림을 노출하지 않고, 학습 종료 시점에만 정산 모달로 일괄 안내한다.
- 모든 도메인 타입은 `shared/types`에서 단일 정의하고 프론트/백 공유. Mongoose 스키마는 이 타입과 일치.
- 점수·성장 누적 등 동시 갱신은 **원자적 연산(`$inc`, `findOneAndUpdate`)/트랜잭션**으로 무결성 확보.
- API는 시딩 더미라도 **실제 DB 상태에 근거**해 응답하며, 성공/검증오류 상태 코드를 실제 결과에 맞게 반환.

## 3. 주요 리스크

### 3.1 제품 리스크

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 동기 부여 요소가 게임처럼 느껴져 학습 본질을 가림 | 사용 목적 왜곡 | 게이미피케이션 용어 배제, 성장 나무/화분을 학습 성장의 시각 은유로만 사용 |
| 성취/목표 난이도 부적절 | 동기 저하·이탈 | 조건/목표값을 `conditionCode`·`targetValue`로 외부화하여 튜닝 |
| 가상 순위가 과도한 경쟁/위축 유발 | 정서 부담 | 순위는 보조 지표로만, 강조 UI 지양 |
| 종료 정산 모달의 정보 과다(성취·퀘스트·점수·성장 동시 노출) | 인지 부하·피드백 희석 | 모달을 우선순위 기반으로 단계적/요약 노출, 상세는 마이페이지 보관함으로 위임 |
| 통합 대시보드의 시각 요소 과다(주변 화분 누적) | 가독성 저하·성능 부담 | 화분 표현을 월 단위로 집약·요약, 상세는 캘린더 드릴다운으로 분리 |
| 시딩 시나리오가 비대표적 | 잘못된 검증 결론 | 대표 페르소나·엣지 시나리오를 시드에 포함, 시드 셋 문서화 |

### 3.2 기술 리스크

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 점수/성장 동시 갱신 경합 | 데이터 불일치 | `$inc`·`findOneAndUpdate` 원자적 연산, 다중 문서 갱신은 트랜잭션 |
| React/Vue 공존에 따른 타입·상태 불일치 | 버그·중복 | `shared/types` 단일 출처, 앱/모듈 단위 프레임워크 경계 명확화 |
| Mongoose 스키마와 shared 타입 드리프트 | 런타임 오류 | 타입을 SSOT로 두고 스키마를 그에 맞춰 작성, 검증 로직 동기화 |
| 시뮬레이터 재생 주기와 실제 타이머 동기화 오차 | 집중 시간 산정 오류 | 서버 ISO 시각 기준 단일화, 이벤트는 `aiEvents`에 누적 기록, FE는 이탈 중 `focusSeconds` 미적립 |
| 종료 정산 결과(`StudySessionResult`)와 영속 DB 상태 불일치 | 잘못된 모달 노출 | 정산은 DB 갱신 결과를 근거로 구성(저장 후 산정값으로 응답), 모달은 서버 확정 결과만 표시 |
| 낙관적 UI와 DB 판정 결과 불일치 | 잘못된 피드백 | 응답 수신 후 reconcile(서버값 우선) 규칙 정의. 단, 정산 모달은 낙관적 미적용 |

### 3.3 구현 리스크

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 비즈니스 로직이 프론트로 유출 | 규칙 위반·중복 | 점수/판정/성장/정산은 백엔드 전용, 프론트는 결과 표시만 |
| 시연 일정 압박으로 임시 코드 누적 | 기술 부채 | P0~P5 우선순위 준수, 임시 코드는 `session_context.md`에 기록 |

| 시드 데이터에 민감정보 혼입 | 프라이버시 | 시드는 가공 더미만, 마스킹·미저장 원칙(`architecture.md` 6장) 적용 |
| Mongo 연결 정보·DB 노출 | 보안 | 연결 문자열은 `.env`로 분리, 커밋 금지 |
