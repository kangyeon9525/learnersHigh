# 러너스하이 (Learners High) — PRD

- 학습 매니지먼트 플랫폼 · 성취·목표·성장 기반 학습 동기 부여 기능 확장

---

## 1. 문서 개요

### 1.1. 프로젝트 개요

- **서비스명:** 러너스하이 (Learners High)
- **서비스 정의:** 학생의 자기주도학습 역량을 향상하기 위해 학습의 전 과정을 하나의 앱에서 통합 관리하는 학습 매니지먼트 플랫폼
- **서비스 목적:** AI 기반 학습 상태 감지 및 자동화된 리포트를 통해 기존의 고비용 1:1 휴먼 코칭을 대체하고, 지속 가능한 자기주도학습 습관 형성
- **동기 부여 설계 원칙(집중 우선):** 학습 도중에는 성취·목표 달성 알림을 노출하지 않아 몰입을 방해하지 않으며, **학습 종료 시점에 모든 보상을 일괄 정산하여 결과 모달로 안내**한다. 누적된 성취·성장 기록은 마이페이지에서 언제든 회고할 수 있도록 한다.

### 1.2 개발 환경 및 기술 스택

- **아키텍처:** 모노레포(Monorepo) 구조 (단일 리포지토리 내 멀티 앱 및 공통 패키지 관리)
- **개발 언어:** TypeScript (프론트엔드/백엔드 전 영역 적용)
- **프론트엔드:** React, Vue (모노레포 내 개별 앱/모듈 단위 공존)
- **백엔드:** Node.js 기반 API 서버
- **데이터베이스:** MongoDB (Mongoose ODM 기반 스키마 모델링, 로컬 인스턴스 또는 Docker/Atlas 연결)
- **테스트:** Playwright (E2E 자동화 테스트)
- **디자인/구현 워크플로우:** Figma 디자인을 기준 소스로 한 바이브코딩 (Figma MCP + Cursor 연동)
- **대상 플랫폼:** 학생 시점의 태블릿 앱 (Tablet-optimized Web/App View)

## 2. 주요 제약사항 및 데이터 시딩 전략 (프로토타입 환경)

본 프로젝트는 시연 목적이므로, **데이터베이스는 실제 MongoDB를 사용**하되 수집이 불가능한 웹캠·실사용자 데이터는 대표 시나리오의 목(Mock) 데이터를 사전 시딩(seed)하여 검증합니다. API는 시딩된 DB 상태에 근거한 실제 응답을 반환합니다.

| **구분**                    | **실제 운영 사양**                             | **본 프로젝트 구현 방식**                                                                                                                                                                                       |
| --------------------------- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **AI 감지**                 | 웹캠 기반 실시간 집중/이탈 감지                | **시딩 데이터 재생:** 웹캠 입력을 얻을 수 없으므로, 사전 정의된 집중/이탈 시나리오 목 데이터를 DB에 시딩하고 시뮬레이터가 이를 일정 주기(예: 30초)마다 재생·주입하여 동작을 검증                                |
| **데이터 영속화**           | 운영 RDBMS (예: PostgreSQL)                    | **실제 MongoDB 사용:** Mongoose ODM으로 컬렉션(`users`, `studySessions`, `milestones`, `goals`, `growthStates`)에 대해 실제 CRUD 수행                                                                           |
| **외부 연동 & 데이터 수집** | 지점 관리자 실시간 알림 / 실사용자 학습 데이터 | **목 데이터 사전 적재 + 실제 응답:** 실사용자·외부 데이터를 수집할 수 없으므로 대표 시나리오 목 데이터를 시딩한 뒤, API는 해당 DB 상태에 근거한 실제 응답을 반환. Playwright E2E로 시딩 데이터 기반 흐름을 검증 |

## 3. 시스템 아키텍처 및 데이터 흐름

### 3.1 디렉토리 구조 (Root-level Split)

프로젝트 루트를 기준으로 `frontend/`와 `backend/`로 명확히 분리하며, 프론트엔드와 백엔드가 함께 참조해야 하는 도메인 타입(TypeScript 인터페이스)은 `shared/` 폴더로 관리하여 워크스페이스 형태로 연동합니다. E2E 테스트는 루트의 `e2e/`에서 Playwright로 통합 관리합니다.

bash

`runners-high/ (Project Root)
├── frontend/                   # 학생 태블릿 앱 (React/Vue)
│   ├── package.json
│   ├── tsconfig.json
│   ├── src/
│   │   ├── components/         # UI 컴포넌트
│   │   │   ├── result-modal/   # 학습 종료 정산 모달(성취/퀘스트 달성 일괄 안내)
│   │   │   ├── growth/         # 성장 통합 대시보드 위젯(메인 누적 성장 나무 + 주변 월간 화분)
│   │   │   └── mypage/         # 마이페이지 성취·성장 보관함 위젯
│   │   ├── pages/              # 화면 단위 라우팅 컴포넌트(타이머, 성장 대시보드, 마이페이지 등)
│   │   ├── api/                # 백엔드 API 호출 유틸리티 (axios/fetch)
│   │   ├── stores/             # 프론트엔드 전역 상태 관리 (Zustand, Pinia 등)
│   │   └── utils/              # 프론트엔드 공통 헬퍼 함수
│   └── ...
├── backend/                    # Node.js API 서버 및 Mock 모듈
│   ├── package.json            # 백엔드 전용 의존성 (mongoose 등)
│   ├── tsconfig.json           # Node.js 환경 설정
│   ├── src/
│   │   ├── server.ts           # 서버 엔트리 포인트 (포트 바인딩 및 앱 실행)
│   │   ├── app.ts              # Express/Fastify 앱 설정 및 미들웨어 초기화
│   │   ├── routes/             # API 엔드포인트 정의 (ex. /api/study, /api/goals)
│   │   ├── controllers/        # 클라이언트 요청(Request) 검증 및 응답(Response) 반환
│   │   ├── services/           # 핵심 비즈니스 로직 (성취/목표 판정, 성장 단계 계산, 종료 정산 집계)
│   │   ├── middlewares/        # 에러 핸들링, 로깅 등 공통 처리
│   │   ├── db/                 # MongoDB 연결 설정 및 Mongoose 모델/스키마 정의
│   │   ├── seeds/              # 웹캠·사용자 목 데이터 시딩 스크립트 (seed.ts 등)
│   │   └── mock-ai/            # 시딩된 집중/이탈 데이터를 주기적으로 주입하는 시뮬레이터
│   └── ...
├── shared/                     # 프론트/백엔드 공통 모듈
│   ├── package.json            
│   └── types/                  # Milestone, Goal, Growth, SessionResult 등 공통 TypeScript DTO
├── e2e/                        # Playwright E2E 테스트
│   ├── playwright.config.ts    # Playwright 설정 (baseURL, 프로젝트/브라우저 등)
│   └── tests/                  # 시나리오별 스펙 (학습 루프, 종료 정산 모달, 성장 대시보드, 리포트 등)
├── package.json                # 루트 워크스페이스 설정 파일
└── .cursorrules                # 바이브코딩용 AI 어시스턴트 프롬프트/컨텍스트 규칙`

### 3.2 핵심 데이터 흐름 (계층형 아키텍처 연동)

본 시스템은 프론트엔드와 백엔드 간 명확한 역할 분리 및 `shared` 패키지의 타입 공유를 통해 안정적인 데이터 흐름을 보장합니다.

1. **이벤트 트리거 (Mock AI 및 태블릿 앱):**
   - **주기적 감지:** 백엔드의 `mock-ai/` 모듈이 사전 시딩된 집중/이탈 시나리오 데이터를 일정 주기(예: 30초)마다 재생하여 API를 호출합니다. (실제 웹캠 입력을 대체)
   - **학습 종료:** 사용자가 태블릿 앱(React/Vue)에서 학습 타이머를 수동으로 종료할 때 최종 세션 데이터가 발생합니다.
   - **집중 우선 원칙:** 학습 진행 중에는 집중/이탈 비정상 상태 **인라인 경고**(비차단, 집중 시간 미적립)만 노출하며, **성취·목표 달성에 대한 알림/모달은 학습 도중 일절 노출하지 않습니다.**
2. **API 요청 및 라우팅 (Frontend → Backend `routes/`):**
   - 프론트엔드의 `src/api/` 계층에서 취합된 학습 데이터를 백엔드로 전송합니다. (예: `POST /api/study/session`)
   - 백엔드의 `routes/`가 해당 요청을 받아 알맞은 `controllers/`로 전달합니다.
3. **요청 검증 (Backend `controllers/`):**
   - `shared/types/`에 정의된 공통 DTO(Data Transfer Object)를 기준으로 클라이언트가 보낸 데이터(Body, Params)의 유효성을 검증합니다.
4. **비즈니스 로직 처리 및 종료 정산 (Backend `services/`):**
   - 유효성이 확인된 데이터를 바탕으로 핵심 로직을 수행합니다.
   - **상태 판정:** 누적 학습 시간 및 집중도를 계산합니다.
   - **종료 정산(일괄 판정):** 학습 종료 시점에 성취 달성 여부, 주기별 학습 목표 완료 판정, 점수 지급량 및 성장 단계(누적 점수 기반 성장 나무·월간 화분) 데이터를 **한 번에 집계**합니다.
   - 집계 결과는 종료 정산 모달에 표시할 `StudySessionResult`(신규 달성 성취/완료 퀘스트 목록, 획득 점수, 성장 단계 변동) 형태로 구성합니다.
5. **데이터 영속화 (Backend `db/` → MongoDB):**
   - `services/`의 연산이 끝나면 `db/` 계층(Mongoose 모델)으로 저장을 위임합니다.
   - MongoDB에 대해 문서 단위 `insert`/`update`를 수행하며, 누적 점수 증가 등은 원자적 연산(`$inc`, `findOneAndUpdate`)으로 처리하여 데이터 일관성을 유지합니다.
6. **응답 및 UI 갱신 (Backend → Frontend):**
   - 저장이 완료되면 `controllers/`를 통해 **실제 DB 상태에 근거한** 처리 결과와 갱신된 유저 상태, 그리고 **종료 정산 결과(`StudySessionResult`)** 를 프론트엔드에 응답으로 반환합니다. (성공/실패·검증 오류 등 상태 코드를 실제 결과에 맞게 반환)
   - 프론트엔드는 전역 상태(Zustand 등)를 업데이트하고, **학습 종료 직후 정산 모달**을 통해 이번 세션에서 달성한 성취·퀘스트와 성장 변화를 일괄 노출합니다. 이후 리포트 및 성장 대시보드 UI를 즉각적으로 리렌더링하여 사용자에게 피드백을 제공합니다.

| **타이머/AI**       | 학습 진행 및 상태 감지 | 스톱워치/타이머 모드 제공. 시딩된 가상 AI 감지 데이터 연동을 통한 비정상 상태 **인라인 경고**(타이머는 계속, 이탈 중 집중 시간 미적립). **(학습 중에는 집중/이탈 경고 외 동기 부여 알림은 노출하지 않음)** |
| **평가/리포트**     | 학습 종료 및 이력 조회 | 종료 시 진척도 및 만족도 5점 척도 입력 후 **종료 정산 모달**로 성취·퀘스트 달성 및 성장 변화를 일괄 안내. 일간/월간 리포트(순공 캘린더, 효율 차트) 및 지점 내 가상 순위 제공.   |
| **라이브러리/코칭** | 부가 기능              | 학습/수업/생활 카테고리 필터링. 코칭 클래스 가상 예약 및 다이렉트 접속(QR/Link) 지원.                                                                                           |

### **4.2 신규 추가 기능**

| **구분**       | **기능명**                              | **세부 요구사항**                                                                                                                                                                                                                                       |
| -------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **성취**       | 학습 성취 시스템 (Milestone)            | 특정 기준(연속 N시간 등) 달성 시 성취 인증 부여 및 높은 점수 지급. **학습 중에는 알림을 띄우지 않고 학습 종료 시 백엔드에서 일괄 판정**하여 종료 정산 모달로 안내.                                                                                      |
| **목표**       | 개인 맞춤형 학습 목표 (Goal)            | 일일/주간/월간 단위 자동 목표(퀘스트) 배정. **학습 종료 및 주기 종료 시 백엔드에서 달성 판정** 및 차등 점수 지급. 달성분은 종료 정산 모달로 일괄 안내.                                                                                                  |
| **정산**       | 학습 종료 정산 모달 (Session Result)    | 학습 종료 후, 이번 세션에서 새로 달성한 성취·완료한 퀘스트·획득 점수·성장 단계 상승 내역을 **하나의 결과 모달로 일괄 노출**. 학습 중 집중을 방해하지 않는 사후 정산 방식. 모달에서 성장 대시보드/마이페이지로 바로 이동 가능.                           |
| **성장**       | 누적 성장 나무 (Lifetime · Growth Tree) | 획득한 점수가 즉시 누적되어 영구적인 단일 나무가 단계적으로 성장(씨앗 → 새싹 → 묘목 → 성목). 성장 통합 대시보드의 **메인(중심) 오브젝트**로 표현. 누적 캘린더 뷰에서 날짜별 성장 이력 조회.                                                             |
| **성장**       | 월간 성장 화분 (Monthly · Plant)        | 매월 초 새 화분(씨앗)으로 초기화되며 당월 점수로만 성장. 성장 통합 대시보드에서 **메인 나무 주변을 채우는 위성 오브젝트**로 배치되어 월별 성취가 함께 꾸며짐. 월말에 성장이 고정(개화)되어 아카이브 캘린더 뷰에서 조회.                                 |
| **성장**       | 성장 통합 대시보드 (Growth Garden)      | 캘린더 단독 표현이 아닌, **한 화면에 전체 그림(정원/풍경)을 구성**. 중심에 누적 성장 나무를 배치하고 주변에 월간 성장 화분들이 둘러싸여 자라나는 형태로, 사용자의 학습 여정을 하나의 장면으로 시각화. 대시보드에서 누적/월간 캘린더 뷰로 드릴다운 가능. |
| **마이페이지** | 성취·성장 보관함 (Collection)           | 마이페이지에서 **획득한 성취(업적) 목록, 완료한 퀘스트 이력, 성장 단계 변화/캘린더**를 모아 확인. 달성/미달성 성취를 그리드로 표시하고, 성장 통합 대시보드 및 상세 캘린더로 진입하는 허브 역할.                                                         |

(참고: 성취/목표로 획득한 1회의 점수는 누적 성장 나무와 월간 성장 화분 양쪽에 동시에 자동 반영됩니다. 모든 달성 안내는 학습 종료 후 정산 모달에서 일괄 노출되며, 이후 마이페이지 보관함에서 영구적으로 회고할 수 있습니다.)

## 5. 핵심 사용자 플로우

**Flow 1. 학습 → (종료 후 정산) → 동시 성장**

1. 사용자가 입실 후 학습 계획을 선택하고 타이머를 시작함.
2. 학습 진행 중에는 집중/이탈 **인라인 경고** 외에 성취·퀘스트 달성 알림이 **노출되지 않음**(몰입 우선). 이탈 시 타이머는 멈추지 않고 집중 시간만 적립되지 않는다.
3. 사용자가 학습을 종료하면 진척도·만족도(5점)를 입력하고, 세션 로그가 백엔드로 전송됨.
4. 백엔드가 성취 조건·퀘스트 달성 여부를 **일괄 판정**하고 점수·성장 단계를 산정하여 정산 결과(`StudySessionResult`)를 반환함.
5. 앱 화면에 **학습 종료 정산 모달**이 떠서 이번 세션의 신규 성취·완료 퀘스트·획득 점수·성장 단계 상승을 한 번에 보여줌.
6. MongoDB에 점수 획득 및 반영 내역이 기록되며, 누적 성장 나무와 월간 성장 화분의 성장 단계가 즉시 상승함.
7. 정산 모달에서 닫기 또는 "성장 보러가기"를 통해 성장 통합 대시보드/데일리 리포트로 이동하여 갱신된 상태를 확인함.

**Flow 2. 성장 통합 대시보드 조회**

1. 마이페이지 또는 성장 탭으로 진입하면, 캘린더가 아닌 **전체 그림(정원 풍경)** 이 먼저 노출됨.
2. 화면 중심에는 누적 성장 나무가, 주변에는 월별로 자라난 월간 성장 화분들이 배치되어 학습 여정이 하나의 장면으로 표현됨.
3. 중심 나무 또는 특정 월간 화분을 선택하면 해당 누적/월간 **캘린더 뷰로 드릴다운**되어, 날짜별 성장 단계와 달성 내역을 조회함.

**Flow 3. 마이페이지 성취·성장 보관함 확인**

1. 마이페이지 내 성취·성장 보관함으로 진입함.
2. 획득한 성취(업적) 그리드, 완료한 퀘스트 이력, 성장 단계 변화를 한 곳에서 확인함.
3. 특정 성취/퀘스트를 선택하면 달성 일자와 획득 점수 등 상세 정보를 조회하고, 성장 통합 대시보드로 이동함.

## 6. 데이터 모델 (공통 Type / MongoDB 컬렉션 매핑)

tsx

`// packages/shared-types
//
// 각 인터페이스는 MongoDB 컬렉션(Mongoose 스키마)과 매핑됩니다.
// Collections: users, studySessions, milestones, goals, growthStates
// 문서 간 관계는 ObjectId 문자열(userId 등)로 참조합니다.
// StudySessionResult는 저장용 컬렉션이 아닌, 학습 종료 정산 모달용 응답 DTO입니다.

export interface StudySession {
id: string; // MongoDB \_id (ObjectId)를 문자열로 직렬화
userId: string; // users 컬렉션 참조
startedAt: string; // ISO String
endedAt: string; // ISO String
focusMinutes: number; // 순공 시간
satisfaction: 1 | 2 | 3 | 4 | 5;
completed: boolean;
aiEvents: Array<{ at: string; status: 'focus' | 'distracted' }>; // 시딩된 목 데이터
}

export interface Milestone {
id: string;
userId: string;
title: string;
conditionCode: string; // 백엔드 판정 매핑용 코드
rewardScore: number;
isAchieved: boolean;
achievedAt?: string;
}

export interface Goal {
id: string;
userId: string;
cycle: 'daily' | 'weekly' | 'monthly';
targetValue: number;
currentValue: number;
rewardScore: number;
isCompleted: boolean;
}

// 사용자당 1개 문서 (growthStates 컬렉션)
export interface GrowthState {
id: string;
userId: string;
// 누적(평생) 성장 나무: 모든 학습 점수가 영구 누적
lifetime: {
totalScore: number; // 누적 성장 점수
currentStage: number; // 나무 성장 단계 (0:씨앗 ~ N:성목)
history: any[]; // 날짜별 성장 이력
};
// 월간 성장 화분: 매월 초기화, 당월 점수만 반영
monthly: {
currentMonth: string; // YYYY-MM
totalScore: number; // 당월 성장 점수
currentStage: number; // 화분 식물 성장 단계 (씨앗 ~ 개화)
archive: any[]; // 월말 고정된 과거 월 기록 (성장 대시보드 주변 화분 렌더링 소스)
};
}

// 학습 종료 정산 모달용 응답 DTO (DB 저장 X, 종료 응답에 포함)
export interface StudySessionResult {
sessionId: string;
focusMinutes: number;
earnedScore: number; // 이번 세션 총 획득 점수
newMilestones: Milestone[]; // 이번 세션에 새로 달성한 성취
completedGoals: Goal[]; // 이번 세션/주기 종료로 완료된 퀘스트
growthDelta: {
lifetime: { fromStage: number; toStage: number };
monthly: { fromStage: number; toStage: number };
};
}`

## 7. 비기능 요구사항 및 개발 우선순위

### 7.1 비기능 요구사항

- **서버-클라이언트 분리:** 상태 변화 및 비즈니스 로직(점수 계산, 성취 판정, 종료 정산 집계)은 철저히 Node.js 백엔드에 위임하여 프론트엔드는 렌더링에만 집중하도록 설계합니다.
- **집중 보호(방해 최소화):** 학습 진행 중에는 동기 부여 알림(성취/퀘스트 모달)을 노출하지 않고, 학습 종료 시점에만 일괄 정산 모달로 안내하여 몰입을 보호합니다.
- **데이터 일관성:** 동시 쓰기 충돌을 방지하기 위해 MongoDB의 원자적 갱신 연산(`$inc`, `findOneAndUpdate`)과 필요 시 트랜잭션을 활용하여 점수·성장 데이터의 무결성을 유지합니다.
- **UI/UX 반응성:** 태블릿 가로 모드에 최적화된 레이아웃을 구성하며, 백엔드 응답 지연을 대비한 낙관적 UI(Optimistic UI) 업데이트 처리를 적용합니다. 단, 종료 정산 모달은 백엔드 확정 결과를 기준으로 노출합니다.
